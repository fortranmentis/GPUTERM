# GpuTerm 1.3.0-beta

## Highlights

- **Ollama and vLLM runtime monitoring.** Register any number of servers by URL and watch them from a new `LLM RUNTIME` card in the monitoring bar. A runtime is a plain HTTP endpoint rather than an SSH session, so the card and its pop-out detail window work with no terminal connected at all. Monitoring is strictly read-only: `/api/ps`, `/api/tags`, `/health`, `/v1/models`, and `/metrics` are the only endpoints called, and no inference request is ever sent — nothing is downloaded, deleted, started, stopped, or restarted.
- **Optional SSH-tunneled polling.** An instance can name a saved SSH profile as its *Reach through*, and its address is then resolved on that host: `http://127.0.0.1:11434` reaches a runtime bound to the remote machine's own loopback. Nothing has to be exposed on the network — no `0.0.0.0` binding, no firewall rule, no `netsh portproxy` — and the traffic rides inside SSH. Direct polling stays the default and is unchanged.
- **Honest gaps instead of invented numbers.** A metric the installed runtime version does not publish is labeled *not supported*; a value not yet read shows as `—`. Neither is ever displayed as `0`. Ollama's request, queue, TTFT, and tokens/s figures are absent by design, because a read-only probe cannot know them.
- **Ollama** — running and installed models merged into one list, model file size, VRAM-resident size and share, estimated non-VRAM residency (labeled as a CPU-offload estimate, never as system RAM), configured maximum context, and remaining keep-alive time.
- **vLLM** — running/waiting/swapped requests, server-wide KV cache usage and headroom, prefix-cache hit rate, prompt and generation tokens per second, request rate, preemption total and per-interval delta, and TTFT P50/P95 plus end-to-end and queue-time P95 interpolated from Prometheus histogram buckets. `vllm:kv_cache_usage_perc` is preferred with a fallback to the older `vllm:gpu_cache_usage_perc`.
- **Failure isolation and clear causes.** Each instance is probed on its own thread with its own timeout and a 5→10→30→60 s backoff, so one dead server neither blocks nor hides the others. A partially unreadable response is reported as `degraded` rather than discarded, and the detail view names the reason instead of showing a bare status.
- **Per-instance configuration** — poll interval (1–300 s, default 5) and request timeout (500–60000 ms, default 3000), an enable/disable toggle, a connection test that saves nothing, and a 15-minute in-memory trend chart drawn in the existing inline-SVG chart style.

## SSH tunnel details

- One SSH connection per profile, shared by every tunneled instance on that host, so Ollama and vLLM on one GPU box produce a single login and a single keepalive stream. One forwarded loopback port per instance, because sharing a port would make two instances share the HTTP client's connection-pool key.
- Built on the `direct-tcpip` forward that already backs ProxyJump. The byte pump is shared verbatim with that path; the new part is a persistent accept loop that opens one channel per connection instead of exactly one for a handshake.
- Connecting never blocks the coordinator. An SSH connect can take ten seconds while the poll loop ticks every 500 ms, so a connect in flight reports `pending` — skipped without being counted as a failure — and a connect that never reports becomes a failure after 20 seconds rather than leaving an instance stuck at "not polled yet".
- The SSH host key must already be trusted before the poller opens a socket. That is decided by reading `known_hosts.json`, so the unknown-host-key sentinel can never escape into a background thread that has no way to show a fingerprint prompt. **Test connection** is the trust bootstrap and does show it, after which monitoring resumes on its own within one poll interval.
- API keys go only into the encrypted `credentials.enc` vault, under an `llm:` key namespace. The key is not a field on the instance record, is never returned to the webview, and is stripped from error text. A locked vault holding a key is reported as such instead of sending an unauthenticated request that the server would reject with a misleading 401.

## Fixes

- Fixed a tunneled instance never recovering after its SSH transport died. The forwarder's accept loop kept running, so the instance looked healthy while every channel open failed, and the poller rebuilt only the forward — on a connection that could never serve again. Forwarders now probe the transport with a keepalive when a channel open fails and report *why* they stopped, so a dead hop tears the connection down and reconnects instead of failing forever.
- Fixed `channel_direct_tcpip` returning `EAGAIN` on a non-blocking session being treated as a hard failure. The ProxyJump path opens its channel while the session is still blocking and so never sees this; without a retry loop a tunnel would bind a local port and then silently serve nothing. The `EAGAIN` constant is pinned by a test against ssh2's own `io::ErrorKind::WouldBlock` mapping.
- A loopback address polled with *Reach through* left on `Direct` now warns, in the form and again on the detail card. Previously the only symptom was a bare "connection refused" that gave no hint the runtime was on another host — the exact confusion the tunnel option introduces. The warning is suppressed where it would be wrong advice: on an already-tunneled instance, and on a healthy local runtime.
- LLM instance mutations read the config file rather than the in-memory copy. If `llm_instances.json` had failed to parse at startup that copy is empty, and writing it back would have deleted every other instance; an unreadable file now fails the save loudly and is surfaced instead of looking like "no instances".
- `test_llm_instance` returns the unknown-host-key sentinel as an error rather than as a status, so the fingerprint prompt can actually run. It previously reported every failure as a successful call with a failed status inside.

## New dependencies

- `ureq 3.3` (`json`, `platform-verifier`) is the only crate added, and the first HTTP client in the project. It was chosen over `reqwest` because the backend is entirely blocking I/O on `spawn_blocking` threads — ureq's agent is a connection pool with no threads and no async runtime, while `reqwest::blocking` spawns a dedicated OS thread running a tokio runtime and its own documentation warns that calling it from inside a runtime panics. It adds 21 crates to the lockfile (rustls, ring, and the platform trust-store shims) rather than activating the hyper/tokio/tower stack for the desktop target, its rustls backend uses `ring` so CI needs neither cmake nor NASM (unlike `aws-lc-rs`), and it does not disturb the vendored OpenSSL chain that `ssh2` already builds. The `platform-verifier` feature is required so that an internal CA already trusted by the operating system works for an `https` runtime address; ureq's default bundled roots would reject it.
- No Prometheus parser crate was added. `prometheus-parse` matches metric names with `\w`, which excludes `:`; every `vllm:`-namespaced metric was verified to vanish silently, returning an empty scrape indistinguishable from a server exposing nothing. `openmetrics-parser` rejects colons and is LGPL-3.0, `nom-openmetrics` is `all_consuming` so one malformed line fails the whole scrape, and `prometheus-scraper` has negligible adoption. The parser is therefore hand-written and handles colon-namespaced names, quoted label escapes, `NaN`/`±Inf`, scientific notation, cumulative histogram buckets, and per-line error recovery.

## Validation

- Frontend: 155 Vitest tests pass, covering the LLM runtime card and detail view, SSH-tunnel selection and its host-key bootstrap, the loopback warning and the cases where it must stay hidden, plus the existing AI DASH, SFTP, terminal, telemetry, saved-profile, and credential-vault suites.
- Backend: 264 Rust tests pass with 2 ignored (one needs host permissions, one needs a live listener). 104 are new and cover the Prometheus parser, both runtime adapters, counter delta and reset handling, histogram quantiles, URL validation and the tunnel-aware duplicate rule, severity thresholds, time-series bucketing and trimming, tunnel scheduling and teardown against a fake SSH backend, and assertions that no payload or error message can carry an API key or an SSH password.
- The tunnel was additionally exercised end to end against a purpose-built `sshd` with the runtime bound to loopback only: correct per-endpoint poll intervals, a 15 KB chunked `/api/tags` body carried intact through the pump, one login serving two instances, an untrusted profile opening no socket at all while its siblings kept polling, recovery from a killed transport, and no orphaned threads or sockets after quitting.
- Static/build checks: TypeScript and the Vite production build succeed, ESLint reports no errors, Clippy passes with warnings denied across all targets, and `git diff --check` passes.
- Release packaging runs natively on GitHub-hosted Windows, Ubuntu, and macOS runners and publishes an NSIS `.exe`, Debian `.deb`, Apple Silicon `.dmg`, and `SHA256SUMS.txt`.
- The macOS job signs nested Mach-O code inside-out, applies a final deep ad-hoc signature to `GpuTerm.app`, verifies it with `codesign --deep --strict`, creates the DMG from that verified bundle, mounts it, and verifies the enclosed app again before upload.

## Notes

- No profile, known-host, app-settings, or encrypted credential-vault migration is required when upgrading from 1.2.3-beta. LLM runtime monitoring adds a new `llm_instances.json`; it is created on first use and its absence is not an error. The tunnel field is optional and omitted when unset, so a file with no tunneled instance is byte-identical to what a build without this feature writes.
- Downgrade caveat: an older build reading a newer `llm_instances.json` ignores `sshProfileId` and would poll that address on the desktop instead of through the tunnel. Remove or disable tunneled instances before downgrading.
- An SSH-tunneled instance keeps a loopback port open for the app's lifetime, reachable by any process on the same machine — the same exposure as a hand-run `ssh -L`, and the reason it is opt-in per instance rather than the default.
- `https` cannot be tunneled. The request would arrive at `127.0.0.1`, so the certificate would be validated against that address and could not match; the combination is refused when you save it rather than failing later with an unexplained TLS error.
- LLM time series are kept in memory for one hour and are never written to disk, so a chart starts empty after a restart. Monitoring stores no prompt or model output — only the documented status, model, and metric fields.
- Ollama binds to `127.0.0.1` by default. Either start it with `OLLAMA_HOST=0.0.0.0:11434` and open the port, or leave it on loopback and use the SSH tunnel; the second needs nothing changed on the runtime host.
- This is a beta prerelease. The Windows installer is not signed by a trusted publisher. The macOS bundle is fully ad-hoc signed for integrity but is not Developer ID signed or notarized, so SmartScreen or Gatekeeper may still require a one-time confirmation.
- The macOS installer is Apple Silicon (`aarch64`) only. Intel Mac users can build from source.
